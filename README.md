# Telegram-бот для термопринтера

Бот принимает текст на русском или английском, через OpenAI выбирает шаблон и извлекает значения, последовательно спрашивает обязательные поля, показывает изображение чека и отправляет его на принтер после нажатия кнопки.

Проект предназначен для домашнего Linux / Raspberry Pi Docker host. Home Assistant, n8n и входящие порты не нужны: Telegram используется через long polling. Эта сборка ещё не подключена к вашему Telegram и физическому принтеру.

## Пример разговора

Вы: «Используй шаблон для еды. Курица с овощами, примечание — для семейного ужина».

Бот: «Какая дата приготовления? Укажите точную дату».

Вы: «07.11.2026».

Бот показывает чек и кнопку «Печатать». До нажатия можно написать: «Измени название на индейку с овощами» — появится новый предпросмотр, старая кнопка перестанет действовать.

## Что потребуется

- Принтер с поддержкой ESC/POS raster и RAW TCP; обычно используется порт 9100. Наличие Wi-Fi само по себе не гарантирует поддержку. Совместимость конкретного YHD-8390 нужно подтвердить по инструкции или пробной печатью.
- IP принтера из интерфейса роутера или его страницы конфигурации. Это не IP Raspberry Pi.
- Telegram bot token, полученный у официального @BotFather.
- Числовой Telegram user ID владельца. Его можно получить через Telegram API: отправьте новому боту `/start`, до запуска приложения вызовите `getUpdates` и найдите `message.from.id`. Не пересылайте токен третьим лицам и не публикуйте URL с ним. После настройки разрешённый пользователь может вызвать `/id` в боте.
- OpenAI API key с доступом к выбранной модели и отдельным API-биллингом. Подписка ChatGPT не заменяет API-ключ.

Токены вводятся в `.env` на вашем компьютере; отправлять их в этот чат не требуется.

## Запуск через Docker Compose

Распакуйте архив на Raspberry Pi Docker host. В папке проекта:

```bash
cp .env.example .env
chmod 600 .env
nano .env
docker compose up -d --build
docker compose logs --tail=50 -f
```

Заполните `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `ALLOWED_USER_IDS` (числовые ID через запятую). Для YHD-8390 уже указан `PRINTER_HOST=10.100.102.91`, порт `9100`; поддержку этого порта нужно подтвердить пробной печатью из домашней сети.

Первый запуск оставьте с `DRY_RUN=true`. Напишите боту `/templates`, затем опишите чек. Кнопка «Проверить печать» проверит обработку задания без отправки на принтер.

Для реальной печати установите `DRY_RUN=false` и примените:

```bash
docker compose up -d --force-recreate
```

Начните с короткой заметки. `PRINTER_WIDTH=576` — ширина в точках, не в миллиметрах. Для некоторых 80-мм принтеров нужна 512, для 58-мм часто 384; точное значение смотрите в self-test/инструкции. `PRINTER_CUT=false` отключает команду резака. Включайте её только при наличии совместимого резака.

Если у этого бота уже настроен webhook, удалите его через Telegram `deleteWebhook` перед long polling. Запускайте только один экземпляр приложения. Принтер и Raspberry Pi должны видеть друг друга по сети; TCP 9100 не следует выставлять в Интернет.

`PRINTER_FEED_LINES=3` задаёт протяжку бумаги после каждого чека. Допустимо
целое число от `0` до `255`, по умолчанию `3`; например, `5` даст больший
отступ, `0` отключит дополнительную протяжку. Отправляется явная команда
ESC/POS `ESC d`, а не пустые строки текста. Перед ней задаётся стандартный
межстрочный интервал (`ESC 2`). Если `PRINTER_CUT=true`, протяжка выполняется
**до** команды резака; работает и при выключенном резаке. Размер протяжки
на конкретной модели нужно проверить пробной печатью. В PNG-предпросмотре
дополнительный отступ не отображается, поскольку это команда механизму подачи.
Документация: [ESC d — протяжка на n строк](https://download4.epson.biz/sec_pubs/pos/reference_en/escpos/esc_ld.html).
После обновления кода выполните `make deploy`; после последующих изменений
только `.env` достаточно `docker compose up -d --force-recreate`.

## Шаблоны и переменные

### Словарные карточки: Word of The Hour

Язык можно указать прямо в Telegram:

```text
/word italian
/word en
/word иврит
итальянский
```

Поддерживаются итальянский (`it`), английский (`en`), иврит (`he`), французский
(`fr`), немецкий (`de`), испанский (`es`) и русский (`ru`). Принимаются названия
на русском и английском. Обычный запрос вроде «Дай слово на итальянском»
тоже выбирает шаблон через AI; если язык не указан, бот спросит его.

Необязательный второй параметр — своё слово или выражение:

```text
/word italian finestra
/word english take off
/word hebrew חלון
```

Для `/word` без аргументов можно задать необязательный язык по умолчанию:

```dotenv
WORD_LANGUAGE=italian
```

Язык в команде имеет приоритет над `.env`. Для своего слова сервис Word of
The Hour не вызывается; перевод на русский и пример с переводом готовит AI.
Без своего слова берётся текущее слово из [официального API Word of The Hour](https://github.com/MichaelWehar/Word-of-The-Hour-API).
**Сервис обновляет слово раз в час; это не случайное новое слово на каждый
запрос.** Ответ сервиса кешируется на час в SQLite для всех пользователей
и языков, включая перезапуски бота. Готовые карточки тоже кешируются по слову,
языку и исходным данным; `/preview` показывает сохранённую карточку без API.

На чеке печатаются язык, слово, русский перевод, пример и его русский перевод.
Если нужный перевод или пример есть в ответе сервиса, он сохраняется. Иначе
недостающее дополняется через настроенный `OPENAI_MODEL` и `OPENAI_API_KEY`.
В частности, русский и иврит имеют ограниченное покрытие у сервиса: если
самого слова на выбранном языке нет, AI переводит английское слово часа.
Происхождение дополнений отмечается в поле `notes` на чеке; AI-текст может
содержать ошибки и не является проверенной словарной статьёй.

Макет находится в шаблоне `word` с `"source": "word"` в `templates.json`.
Входные поля: обязательное `language`, необязательное `word`. Выходные поля:
`language`, `word`, `translation_ru`, `example`, `example_ru`, `provider`, `notes`.
Можно менять подписи, размер, `hide`, инверсию и разделители. Иврит печатается
справа налево; для Pillow без RAQM добавлен `python-bidi`. Генерируемый иврит
используется без огласовок. Печать выполняется только по кнопке с учётом `DRY_RUN`.

OpenAI получает выбранное слово, язык и доступные словарные данные для подготовки
карточки; Word of The Hour получает только запрос своего общего JSON, без
ваших сообщений и заданных слов. Запросы OpenAI оплачиваются как обычные API-вызовы.
Формат ответа реализован по [OpenAI Docs: Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
После обновления выполните `make deploy`: добавлены модуль `vocabulary.py` и
зависимость `python-bidi`. На Docker-машине также должен быть обновлён
смонтированный `templates.json`.

### Погода на день

Добавьте в существующий `.env` город и, при необходимости, двухбуквенный код
страны. Например (замените город на свой):

```dotenv
WEATHER_CITY=Haifa
WEATHER_COUNTRY_CODE=IL
```

Используется первый найденный город; на чеке печатаются его название, регион
и страна, чтобы можно было проверить выбор. Для одноимённых городов укажите
страну или регион в `WEATHER_CITY`, например `Paris, France`.
Поиск сначала выполняется на русском; если результатов нет, повторяется на
английском с тем же названием и кодом страны. Например, подходят
`WEATHER_CITY=Petah Tikva` или `WEATHER_CITY=Петах-Тиква` при
`WEATHER_COUNTRY_CODE=IL`.
Часовой пояс
определяется по координатам города, независимо от часового пояса Docker host.
Без этих настроек остальные функции бота продолжают работать.

Команды: `/weather` — сегодня, `/weather tomorrow` — завтра,
`/weather YYYY-MM-DD` — конкретная дата в пределах ближайших семи дней.
Работают также «Распечатай погоду на завтра» и голосовые запросы: AI выбирает
шаблон и дату, а реальные значения загружаются из Open-Meteo. Город всегда
берётся из окружения, его нельзя менять сообщением боту.

На чеке: максимум/минимум температуры в °C, погодные условия, максимальная
почасовая вероятность осадков за день и почасовые температура/вероятность
осадков. **Максимум почасовых вероятностей — не вероятность хотя бы одного
дождя за сутки**; осадки включают также снег. Отсутствующие значения отмечены
`н/д`, не заменяются нулём. День и часы относятся к местному времени города.

Макет `weather` находится в `templates.json` с `"source": "weather"`.
Можно менять строки и подписи, удалить поле `hourly` для короткого чека.
Доступные выходные поля: `location`, `date`, `temperature_max`, `temperature_min`,
`precipitation_probability`, `conditions`, `hourly`, `timezone`, `provider`.
Входное поле `date` необязательное; без него используется сегодня.
Настройки заголовка, разделителей и протяжки бумаги работают как обычно.
Прогноз сначала показывается в Telegram; физическая печать только по кнопке.
`/preview` повторяет сохранённый прогноз, `/weather` загружает свежий.

Данные получаются через [Open-Meteo Forecast API](https://open-meteo.com/en/docs)
и [Geocoding API](https://open-meteo.com/en/docs/geocoding-api). Для личного
некоммерческого использования выбран публичный API без ключа. Сервис получает
название города и координаты; прогноз сохраняется в SQLite и отправляется
в Telegram изображением. Сам прогноз не передаётся в OpenAI.
После обновления кода и `.env` выполните `make deploy`; убедитесь, что на
Docker-машине обновлён и смонтированный `templates.json`.

### Задачи Jira Cloud

Настройки Jira читаются только из переменных окружения. Docker Compose передаёт
их из существующего `.env`; добавьте туда (не заменяйте весь файл):

```dotenv
JIRA_BASE_URL=https://onsetinc.atlassian.net
JIRA_EMAIL=your-email@example.com
JIRA_API_TOKEN=your-api-token
```

Для токена **без scopes** достаточно этих трёх переменных. Для токена **со scopes**
также задайте `JIRA_CLOUD_ID`: запросы пойдут через
`https://api.atlassian.com/ex/jira/{cloudId}`. Cloud ID можно получить из
`https://onsetinc.atlassian.net/_edge/tenant_info`. Токен должен разрешать чтение
задач; аккаунт должен иметь доступ к нужному проекту и задаче.

После обновления кода и `.env` выполните `docker compose up -d --build`.
Без настроек Jira остальные функции бота продолжают работать.
При запуске без Docker экспортируйте переменные в окружение процесса;
сам Python-приложение `.env` не читает.

Напишите `/jira PROJ-123`, просто `PROJ-123` или «Распечатай баг PROJ-123».
Голосовое сообщение с распознанным ключом тоже поддерживается. Укажите полный
ключ с префиксом проекта, а не только число.
Можно также попросить «Распечатай задачу из Jira»: AI выберет шаблон и спросит
недостающий ключ. Для шаблона с `"source": "jira"` AI заполняет только входное
поле `issue_key`, затем бот загружает остальные значения из Jira.
Бот получает заголовок, статус, исполнителя, дату создания, стандартное поле
срока `duedate`, приоритет и ссылку. Отсутствующие поля отмечаются на чеке.
Дата создания отображается в часовом поясе, указанном в ответе Jira.
Если срок хранится в вашем custom field или спринте, он пока не используется.

Печать выполняется только по кнопке после предпросмотра, с учётом `DRY_RUN`.
Макет Jira находится в `templates.json` в шаблоне `jira`. Меняйте `title`,
порядок `lines`, подписи `label` и размер `large`, как в других шаблонах.
Параметр `"invert": true` у текстовой строки печатает её белым по чёрному,
например `{"field": "key", "large": true, "invert": true}`. Если текст
переносится, инверсия применяется ко всем строкам этого поля. Боковые поля
бумаги, соседние строки и QR-код остаются без инверсии. Предпросмотр показывает
тот же результат, который отправляется на принтер.
Для строк доступны поля `key`, `summary`, `status`, `assignee`, `created`,
`due`, `priority`, `url`, `issue_type`, `issue_icon`; поле `issue_key` в `fields` используется для запроса.
В строке ключа `"icon": "issue_icon"` добавляет значок типа задачи перед ключом.
Тип берётся из поля Jira `issuetype`; его значок загружается из Jira (PNG или
SVG) и переводится в чёрно-белое изображение для печати. Это работает и для
Improvement, Test, Service Request, Problem, Change, Incident и пользовательских
типов, независимо от их названия. Для загрузки используются адрес вашего
сайта Jira и API gateway; произвольные внешние адреса не загружаются.
Если изображение недоступно, используются локальные значки стандартных типов;
для неизвестного типа — общий ромб. Для scoped-токена доступ к аватарам может
требовать `read:avatar:jira`. Подзадачи также определяются по флагу `subtask` Jira.
Изображение сохраняется вместе с черновиком, поэтому `/preview` не скачивает
его повторно. SVG обрабатывается библиотекой `resvg-py`; после обновления
выполните `make deploy`, чтобы установить новую зависимость.
Значки совместимы с `invert`. Чтобы убрать значок, удалите `icon` из
строки шаблона. `To Do` — статус задачи и отображается в поле `status`.
Для сохранённых ранее предпросмотров повторите `/jira KEY-123`, чтобы загрузить тип.
Ссылка на задачу по умолчанию выводится как QR-код: `{"qr": "url"}` вместо
текстовой строки `{"field": "url"}`. QR-код содержит обычную HTTPS-ссылку на
задачу. После сканирования она откроется в приложении Jira, если телефон
настроен открывать такие ссылки в нём, либо в браузере. Авторизация и права
доступа Jira по-прежнему необходимы. QR-код виден и в предпросмотре Telegram.
Для первого обновления с QR-кодами пересоберите образ (`make deploy`),
поскольку добавлена зависимость `qrcode`.
Шаблоны без `source` заполняются AI как раньше. После изменения шаблонов
выполните `docker compose restart`.
`/preview` повторно показывает сохранённые данные; повторите `/jira PROJ-123`,
чтобы получить свежие данные. API Jira вызывается только на чтение; поля задачи
не меняются. Данные Jira не передаются в OpenAI: они сохраняются в локальной
SQLite и отправляются в Telegram в виде изображения чека. Для голосового
запроса OpenAI по-прежнему получает аудио для распознавания.

Документация: [авторизация Jira Cloud](https://developer.atlassian.com/cloud/jira/platform/basic-auth-for-rest-apis/),
[получение задачи](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/#api-rest-api-3-issue-issueidorkey-get).

В `templates.json` есть `word`, `weather`, `jira`, `food`, `task`, `shopping`, `note`. Шаблон — объект с названием, описанием, полями и строками.

Печать верхнего заголовка (`title`, например `JIRA` или `СПИСОК ПОКУПОК`)
управляется общей переменной окружения `PRINT_SOURCE_NAME`:

```dotenv
PRINT_SOURCE_NAME=false
```

`true` печатает название, `false` полностью убирает его вместе с занимаемым
местом. По умолчанию `true`. Настройка действует на все шаблоны и предпросмотр;
содержимое `lines` остаётся без изменений. Название в списке `/templates` и
служебное поле `source` (способ заполнения: `word`, `weather`, `jira` или `ai`) от неё не зависят.
После изменения `.env` примените `docker compose up -d --force-recreate`.
При первом обновлении кода потребуется пересборка через `make deploy`.
Создайте новый предпросмотр: изображения на уже отправленных кнопках печати
сохраняют прежний вид.

Любой элемент массива `lines` можно временно скрыть через `"hide": true`:

```json
[
  {"field": "assignee", "label": "Исполнитель: ", "hide": true},
  {"text": "Дополнительная подпись", "hide": true},
  {"separator": true, "width": "0.5mm", "hide": true},
  {"qr": "url", "hide": true}
]
```

Скрытый элемент полностью пропускается при отрисовке предпросмотра и печати,
без пустого места.
Для поля с `icon` или `invert` скрывается вся строка. Чтобы вернуть элемент,
поставьте `"hide": false` или удалите `hide`; без параметра элемент видим.
Используйте JSON-значения `true`/`false`, без кавычек. Шаблон продолжает
проверяться, а обязательность входных полей и получение данных не меняются.
Верхний `title` управляется отдельно через `PRINT_SOURCE_NAME`.
После изменения `templates.json` выполните `docker compose restart` и создайте
новый предпросмотр — старые кнопки печатают сохранённое изображение.

В любом месте массива `lines` можно вставить горизонтальный разделитель:

```json
{"separator": true, "width": "2mm"}
```

`width` — толщина линии, строка с единицей `mm` или `em`, по умолчанию
`"2mm"`; например, `"0.3mm"` или `"0.1em"` задаст тонкий разделитель.
`1em` равен размеру шрифта разделителя: 26 точек по умолчанию, 34 при
`"large": true`. Это размер шрифта, а не высота строки с отступами.
Длина линии равна области печати между
боковыми отступами. Над и под линией остаётся по 8 точек свободного места.
Для перевода миллиметров в точки используется `PRINTER_DPI` из окружения,
по умолчанию `203` (2 мм округляются до 16 точек). Если разрешение принтера
другое, задайте его в `.env`. Разделитель — отдельная строка массива:

```json
[
  {"field": "summary", "large": true},
  {"separator": true},
  {"field": "status", "label": "Статус: "},
  {"separator": true, "width": "0.1em"},
  {"qr": "url"}
]
```

Старый числовой параметр `width_mm` поддерживается для существующих шаблонов;
в новых используйте `width`. Одновременно указывать оба параметра нельзя.

Пример пользовательского шаблона:

```json
{
  "parcel": {
    "title": "ПОСЫЛКА",
    "description": "Записка для посылки: получатель и содержимое",
    "fields": {
      "recipient": {"question": "Кому предназначена посылка?"},
      "contents": {"question": "Что внутри?"},
      "comment": {"question": "Добавить комментарий?", "required": false}
    },
    "lines": [
      {"field": "recipient", "label": "Кому: ", "large": true},
      {"field": "contents"},
      {"field": "comment"},
      {"text": "Спасибо!"}
    ]
  }
}
```

Добавьте `parcel` к существующим шаблонам, сохранив корректный JSON, затем `docker compose restart`. Бот читает шаблоны при старте. Поле обязательно по умолчанию; `required: false` делает его необязательным. Произвольные исполняемые выражения не поддерживаются. Вариант с `{field: "recipient"}` — это подстановка переменной, эквивалентная `{{recipient}}` в текстовых шаблонах. Создание шаблонов выполняется редактированием файла; чат предназначен для выбора и заполнения готовых шаблонов.

При повторном заполнении того же шаблона бот сохраняет предыдущие поля: для нового независимого чека используйте `/cancel`. Команды: `/templates`, `/preview`, `/cancel`, `/id`, `/help`. Поддерживаются голосовые сообщения Telegram до 2 минут и 10 МБ. Бот показывает расшифровку, затем заполняет шаблон и спрашивает недостающее. Печать — только по кнопке. Фотографии и аудиофайлы, отправленные как документы, не разбираются. Для распознавания используется `TRANSCRIPTION_MODEL` (по умолчанию `gpt-4o-mini-transcribe`); при отсутствии переменной применяется значение по умолчанию. Для локального запуска установите также ffmpeg. Docker устанавливает его автоматически.

## Надёжность и данные

- Принимаются только личные сообщения от `ALLOWED_USER_IDS`; группы игнорируются.
- AI выбирает шаблон и значения, но не создаёт команды принтера. Неизвестные поля отклоняются. Относительные даты лучше заменять точными.
- Русский и английский печатаются как bitmap с DejaVu Sans. Это устраняет зависимость от кодовой страницы принтера. Иврит, сложное направление текста и emoji в этой версии не проверены.
- Предпросмотр соответствует сохраняемому bitmap. Кнопка действует 30 минут. Редактирование чека отменяет предыдущую кнопку.
- Состояние хранится в SQLite в Docker volume `bot-data`. Нажатие фиксируется **до** отправки; повторный callback или перезапуск не отправит тот же job заново. При сбое во время отправки результат неопределён: возможна частичная печать. Автоповтора нет; осмотрите бумагу и создайте новое задание через `/preview`.
- Сообщения Telegram также фиксируются перед обработкой: при аварийном завершении текущее сообщение может потребоваться отправить повторно. Это осознанный выбор в пользу отсутствия автоматических повторов печати.
- Сообщение «данные отправлены» означает успешную передачу TCP, а не подтверждённый выход бумаги.
- Telegram получает переписку и изображения предпросмотра; OpenAI получает текст, описание шаблонов и текущий черновик, а для голосовых сообщений — также аудиозапись. Распознавание оплачивается отдельно в рамках API. Временные аудиофайлы удаляются после конвертации. В Responses API передаётся `store: false`; это не обещание полного отсутствия хранения со стороны провайдера. SQLite содержит последний черновик каждого пользователя и изображения заданий. Автоочистки в этой версии нет. Не используйте для секретных документов.
- `/cancel` очищает текущий черновик и закрывает ожидающие задания; архив заданий не удаляет. `docker compose down -v` удаляет весь том с черновиками и историей (не делайте этого, если они нужны).

Демонстрационный чек визуально проверен. Дополнительно проверены передача расшифровки в шаблон, ограничения голосовых сообщений, отказ при ошибке распознавания и формат WAV-запроса с фикстурой. ## Обновление установленного контейнера: голосовые сообщения

Сохраните свой `.env`. Распакуйте новую версию в отдельную папку и скопируйте из неё **bot.py и Dockerfile** в существующую рабочую папку. Этих двух файлов достаточно для обновления этой версии. Не заменяйте свой `.env`, `templates.json` или `compose.yaml`.

Из прежней рабочей папки выполните:

```bash
docker compose up -d --build
docker compose logs --tail=30
```

Пересборка обязательна: новый образ содержит ffmpeg. Данные в существующем Docker volume сохраняются. Новая переменная окружения необязательна; для выбора модели добавьте `TRANSCRIPTION_MODEL=gpt-4o-mini-transcribe` в `.env`.

Отправьте боту голосовое сообщение: «Используй шаблон заметки: купить молоко и хлеб». Сначала появится расшифровка, затем предпросмотр. При `DRY_RUN=true` реальная печать по-прежнему выключена.
